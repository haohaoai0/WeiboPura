# Fluo 全局交互审查（源码阶段）

## 范围与证据边界

审查当前工作树（包含尚未提交的修改），覆盖 Index、首页信息流、发现/搜索、搜索结果、用户主页、详情/楼中楼/转评赞、图片预览、视频、发帖/转发编辑器、内置浏览器，以及窗口键盘事件和缓存层。未修改生产源码、未构建或部署。

本轮 127.0.0.1:8712 未发现监听端口，因此没有真机遍历或录屏证据；这不代表 Mac 的 USB 手机断开。以下“确认”指源码路径确认，不等于真机复现。系统返回优先级、组合转场观感、折叠旋转和视频遮挡行为须真机核验。未声明覆盖所有历史贴吧页面。

## P1：操作语义与状态连续性

### 1. 收起评论编辑器会丢失回复对象，但保留草稿【确认】
- `pages/WeiboPostDetail.ets:638` 的 closeCommentEditor 清空 replyTargetComment，不清 commentDraft；底部入口也清回复对象（约 1931 行）。
- beginCommentReply 设置对象；发送时通过 replyTargetComment?.id 决定回复目标（1143 行）。
- 路径：回复 A → 输入文字 → 收起 → 点底部草稿 → 发送。文字仍在，对象已变为整条微博。
- 修复：草稿与 postId/replyId/replyUserName/附件形成一个编辑上下文；“收起”不等于“取消回复”；切换对象必须显式告知。

### 2. 图片缺少来源连续性，按钮退出与系统返回不共用处理【确认实现缺口】
- `pages/ImagePreview.ets:80–150,437–449`：进入整体 0.96→1，退出整体 1→0.98 + 淡出 + 160ms 后 router.back。
- 微博入口只传 urls/index/pictureVideos，不传来源几何或来源元素；未发现本页 onBackPress 接入 closePreview。
- 路由返回能回原页面，但视觉上没有“从点击的图进入、回到对应图”。路由动画与自定义缩放的实际叠加须录屏。
- 修复：图像自身承担过渡，控制栏不跟图缩放；统一按钮/系统返回/手势的关闭协议；切图后有对应可见缩略图则回该图，否则只淡出，禁止飞向无关坐标。
- 双击缩放也未利用点击坐标，当前是中心放大；应保留手指关注点。

### 3. 根导航分栏状态维护不统一【确认】
- `Index.ets:204–239`：>=1200vp 且 contentDestinationOpen 才 Split，openContentDestination 手动预置状态。
- Index 部分消息/富文本入口直接 pushPath（如 1161、1165 行），不走该方法。
- 详情、主页 popRoute 同步 split 状态；搜索结果 popRoute（224 行）只 pop；浏览器也直接 pop 或默认返回。
- 可能造成同一宽度因入口不同分栏不同，或搜索返回根后保留旧状态。
- 修复：在导航栈变化处集中同步；所有入口共享打开/关闭策略，不依赖页面作者手工补调用。验收最后一个目的页关闭、嵌套目的页返回、分栏时切 Tab、折叠旋转。

### 4. 信息流“转发/评论/神评”没有携带操作意图【确认】
- `WeiboHomeTab.ets:945–975,1013–1044`：转发、评论和神评都只调用 openPost。
- 路由没有初始 tab、评论锚点或编辑意图，所以都落到详情默认位置。神评没有传 commentId。
- 修复：正文→正文；评论→评论区（或明确约定打开编辑器）；转发统计→转发列表，转发操作→转发编辑器；神评→对应评论。避免一个“转发”控件兼任两种含义。

### 5. 点赞、关注缺少跨页面统一回写【源码风险高，待端到端复现】
- Home、SearchResult、UserProfile 各自维护 posts/users 和局部状态；服务 setLike/followUser/unfollowUser 只发请求解析，不广播变化。
- 已检查页面没有统一按 postId/userId 的实体订阅；身份变化 watch 不等于实体变化同步。
- 验收：首页→详情点赞→返回；搜索用户→主页关注→返回；同作者多卡片同步。不能用全列表刷新替代，否则破坏滚动位置。
- 修复：以实体 ID 合并变更和版本，更新所有保留页面与缓存，失败回滚。

### 6. 发帖/转发关闭没有草稿保护【确认】
- `components/WeiboComposeDialog.ets:136` 关闭按钮直接 controller.close；Index:767 每次新建 dialog；文本、附件是组件局部状态。
- 没有草稿保存或有内容时的关闭确认；弹窗系统关闭/遮罩在提交中的阻止策略也未集中实现。
- 修复：区分收起、保存草稿、放弃；发送中防止重复发送和误关闭；选图返回恢复同一编辑会话。

### 7. 详情页面解除键盘监听的范围过大【确认代码，需窗口行为验证】
- `WeiboPostDetail.ets:171,189` 匿名 on + 不指定回调的 off('keyboardHeightChange')。
- EntryAbility:231 也注册同名事件，且已有全局 keyboardHeight 状态源。另有 avoidAreaChange 兜底，不应断言所有键盘避让必定失效。
- 风险：退一层详情时删除其他仍需要的监听，嵌套详情/返回编辑器行为不稳定。
- 修复：只由 Ability 管理全局键盘高度，或保存并只注销自身回调。

## P2：布局稳定与加载、搜索连续性

### 8. 三图排版不是真正的 3:4、未顶部对齐【确认；纠正此前完成声明】
- Home/Detail 三图：网格 maxWidth 540，三列，单元固定高 180，ImageFit.Cover。
- 最大宽度下单元宽约 (540-gap*2)/3，接近正方形而非 3:4；小屏比例又变化。
- 长图标签仅由“数量=3”决定，不判断原图宽高；未设置顶部对齐。
- 当前详情还是正文+评论单一滚动列，并没有原型 A 的横屏左右独立滚动实现。
- 修复：由有效宽度和真实图像元数据计算比例；长图按比例识别、顶部裁剪；保留 GIF/实况标识；不要把一项 maxWidth 当成完成折叠屏适配。

### 9. 详情正文可被无关请求阻塞【确认】
- Detail.aboutToAppear 先 await loadCurrentAccountProfile，再延迟 50ms 取路由并加载帖子。
- 无缓存 loadPost 中 loading 一直持续到分享预览准备和评论加载之后，UI 在 loading 时隐藏正文分支；presentPostContent 动画却在这之前执行。
- 结果：正文已返回仍可能只见转圈；实际内容挂载时动画可能已结束。缓存和非缓存路径体验不同。
- 修复：先显示正文/缓存，评论独立状态；账户头像、分享预览并行或按需；不要用额外缩放掩盖延迟。

### 10. 搜索历史只有发现页入口写入【确认】
- 全局检索 weiboSearchHistory/WEIBO_SEARCH_HISTORY：读写集中在 WeiboHotSearch。
- SearchResult 内重新搜索及其他搜索入口没有统一记录服务；发现页异步恢复也没有合并正在新增的历史的版本保护。
- CacheManager.put 确实 flush，但内部吞写入错误；“调用 put”不是重启验收证据。
- 修复：统一 SearchHistoryStore，所有用户提交搜索走同一入口；初始读取与新增/清空串行化。验收杀进程、立即退出、重新搜索和清空后重启。

### 11. 搜索分类切换没有保留分类阅读状态【确认】
- SearchResult.switchTab 清空 posts/users/highlightUser 并重拉第一页；请求结束后延迟 100ms scrollEdge(Top)。
- 切用户后再回综合，原先阅读位置和已加载结果丢失；延迟滚动有打断用户新操作的风险。
- 修复：按 query+category 保留结果、分页、滚动锚点；新关键词才重置；取消失效的延迟动作。
- 详情转评赞共用 Scroller 且 switchDetailTab 没有锚点策略：长列表换短列表的跳动需真机验收。

### 12. 视频只在组件销毁时暂停【代码缺口，待真机复现】
- WeiboVideoPlayer 仅 aboutToDisappear 暂停，没有目的页隐藏/应用后台/可见面积的统一处理。
- Navigation 页面被覆盖不等于组件必然销毁，可能后台继续播放/计时；不能据源码直接声称已听到串音。
- 修复：结合 destination 生命周期和应用前后台管理播放；退出全屏回同一播放器实例和时间点；不要擅自重新播放。
- 官方参考：https://developer.huawei.com/consumer/cn/doc/harmonyos-faqs/faqs-arkui-401

### 13. 内置网页加载指示器改变正文布局【确认】
- WeiboBrowser:50 在 Column 中条件插入 LoadingProgress，上下文 Web 使用 layoutWeight；每次导航开始/结束占用高度发生变化。
- 修复：固定顶部进度槽或覆盖式进度，不挤动网页；保留当前“网页内返回优先 + 独立关闭”的良好语义。

### 14. 触控目标偏小【确认尺寸，实际命中需真机】
- 首页操作行高 34vp；发帖关闭按钮 32x32vp。视觉小图标可保留，命中区域应扩展至约 44–48vp。
- 检查嵌套卡片/图片/作者/话题点击，确保子动作不同时打开整张卡片。

## 统一验收规则

1. 页面返回必须回原入口、原 Tab、原列表项目和偏移；不因状态同步刷新整页。
2. 返回先处理最上层临时态（按系统键盘行为验证），再退出当前目的页；关闭与返回区分清楚。
3. 图片来源转场与页面导航转场各司其职；来源不可用时淡出降级，不虚构缩略图坐标。
4. 有草稿时收起保持目标、内容、附件；改变目标/放弃内容必须显式。
5. 同一实体的点赞/关注/收藏跨保留页面一致。
6. 横竖屏、折叠和分屏按窗口有效宽度计算；保留当前内容和滚动锚点。
7. 真机录屏覆盖：发现→搜索→作者→帖子→原帖→图片→逐层返回；首页评论/神评入口；回复收起重开；发帖选图取消；视频全屏与后台；搜索分类往返。

建议实施顺序：回复上下文/草稿安全 → 统一路由与状态回写/键盘生命周期 → 图片转场和实际响应式图片 → 加载与分类切换 → 真机逐路径录屏验证。保持现有 HDS 顶栏和底部 Dock 材质，不借审查扩大视觉重设计范围。
